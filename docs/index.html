allocation

Portfolio construction that updates as data arrives.

Python estimators that follow scikit-learn and skfolio conventions. Each one updates its weights from new observations without starting again, and works when assets enter and leave the universe.

Why the weights move smoothly

Weights are a function of a covariance estimate, which is a function of the data. For minimum variance and its relatives the first function is smooth, so a smooth covariance estimate is enough.

Three other things make weights jump, and each has a remedy here.

Source of jumpsRemedyWhere
Simulation noiseKeep the random seeds fixed and re-colour the same pathsThurstone portfolio polishing
Re-clusteringOrder assets along a spectral coordinate, not a dendrogramSchur bridge, hierarchical risk parity
Bounds that start or stop bindingKeep solutions in the interior; apply bounds with a barrierRisk parity, constraints

Why a separate package

(Hi Max and Hugo.) skfolio is the scikit-learn-native portfolio library, but it is batch: a changing universe is handled by NaN/incomplete-data mechanics, not by carrying per-asset state across streaming updates. allocation is the online complement — partial_fit, a keyed dynamic universe (in the spirit of precise), and turnover control by construction — while staying API-compatible so each estimator can be contributed upstream. Previously I worked with Hugo to put the original Schur method into skfolio, so maybe we'll do the same here; and note also the river-compatible methods (learn_one / predict_one) for changing universes. It is all MIT-licensed and meant to be upstreamed — take anything here and improve on it.
